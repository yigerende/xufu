# 新提链＋旧浏览器付款

新增第四个整套选项 `cslive_browser`，与旧浏览器、旧 HTTP、新 cs-live 完整流程并列。配置保存后只影响新申请，默认值和已有选择不改变。

## 执行顺序

1. 受理网页/API 申请时校验完整 Session、浏览器运行时、套餐长短链配置；一次随机保存正式账单并冻结服务费。
2. 原单固定 `checkout_runs.flow=cslive`、`payment_runs.executor=browser`；不创建 `subscription_protocol`，由新提链任务和原浏览器付款任务执行。
3. cs-live `CreateCheckout` 经原订单代理完成刷新授权、账号检查、一次创建结账。提链接口没有提交卡资料、确认付款或取消订阅的权限。
4. 仅接受同一结账单的官方长链/短链。成功结果中的最新 AT 与第一方会话 Cookie 校验账号、邮箱、有效期后，与链接一起加密保存到原单。授权字段不进入 JSON/格式化输出；不导入付款/设备检查点，不延长授权保留期限。
5. 原旧浏览器执行器打开该链接，使用本单原账单、原代理和最新登录 Cookie；计算税费、核对金额和出口后，一次确认付款。官方 SDK 处理页面请求与验证，未知结果只核实原交易。
6. 付款成功后沿用旧流程：查订阅和套餐，授权拒绝时刷新保存新 AT 后再查；取消续费前主动刷新，保留续费则不取消。后台流程和长短链设置后续变更不影响本单。

独立结账链接菜单在此选择下只执行新提链，没有付款任务。管理员按本单持久记录展示“新提链 → 旧浏览器”，客户/API 不返回内部执行器或敏感上下文。

## 验证范围

测试使用虚构卡资料、内存上游响应和独立 PostgreSQL。覆盖长链/短链、保留/关闭续费、配置切换后的固定路径、原代理/IP和账单、刷新凭据、一次付款、幂等回放、入口权限及隐私。未发起真实付款；验证通过不保证上游免验证或实际付款成功。

本次独立 PostgreSQL 18872 全量 `go test ./... -count=1` 通过：cslive 2.065s、platform 377.436s；针对性流程测试25.770s，`go vet ./...`、前端check/build和diff检查通过。新增异常回归确认提链结果不明、账号不符或缺失刷新授权时不启动浏览器付款，也不重复创建结账。浏览器脚本及依赖未变化，Linux运行时复用上一版本67项全通过记录；正式发布另验证本版本Linux构建、提链/授权单测和前端资产。
