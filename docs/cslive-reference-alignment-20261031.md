## 验证接续的修正

原包 CLI `Pay` 在提供 TLS 证书、付款返回 `action_required` 且检查点有效时自动准备十分钟验证入口，并等待用户打开页面。页面中的继续按钮才触发 `retrievePaymentIntent`，核对原交易 ID/状态后调用 `handleNextAction`。收到浏览器结束通知后执行 `Recover`；没有通知、入口超时或关闭时保留原交易状态。

本项目此前 `continuePaymentAction(..., nil)` 直接返回，整套任务没有准备入口。本次恢复上述时序：同一任务保存原检查点、保持租约，自动准备一个最长十分钟的管理员入口；打开入口后进入原包页面，由操作者点击继续。原任务只运行一次 SDK，再读取原交易；SDK 回调不是扣款证据。关闭或超时保留原单待核实，不创建 Checkout、不重新调用 Pay，也不因核实仍待验证而循环启动 SDK。

网站与原 CLI 的必要接入区别是：终端入口改为管理员订单详情；原包页面运行在服务器私有浏览器，以继续使用原订单代理及出口检查。只有认领入口的管理员可以查看和操作，同一管理员重复打开复用原会话；其他管理员不能接管。Session、原 PI secret、代理凭据不返回到 API、页面源码或日志。入口等待和页面处理共用十分钟期限，且不能超过原代理/任务期限。

已暂停的历史订单保持原状态。管理员可使用既有“继续原付款验证”接续，或核实原单后自动准备验证入口。发布不重放历史订单。验证过程中仍按现有规则检查原代理，IP 漂移、过期或租约失效停止。进度记录将额外验证标为待处理；不再将尚未启动的 SDK 记为自动执行中。
