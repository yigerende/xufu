# 支付链条与固定代理会话

运营控制台 → 支付全监控 → 订单详情 → 办理结果与阶段进度。

2026-10-31 更新：顶部摘要显示原单办理组合、目标套餐、报价/有凭据的实收、服务费、本轮明确出口比对结果和生效/续费状态。下方按提链、账单税费、付款、生效、续费、结果合并为六个阶段；开始/接口返回/结束不再独立占行。成功阶段收起、异常阶段展开，Session 刷新归入对应业务阶段。完整日志保留在折叠的技术日志中，可筛选异常/网络。阶段耗时取起止区间，不累加嵌套请求耗时。

以付款及订单保存的权威业务状态作为成功依据；HTTP 200 或过程completed不证明已付款/关闭续费。历史未保存初始价、税额、实际套餐有效期及取消请求分类时明确标注未记录，不推算、不将日志数当作付款或取消数。缺少明确exit_ip_matched时不显示出口一致。仅改管理员呈现，客户API不增加内部字段。

对外 `/docs` 与 `/api/openapi.json` 只说明客户接入所需的业务操作、参数、权限、金额、结果和错误处理，不提供内部付款组合或后台配置选择。兼容付款接口注明仅适用历史单独付款订单，新订阅一次提交后查询原订单；不引导用户混搭内部执行器。公开文档版本 1.6.5，接口路径和请求处理实现未改变。

本次呈现层验证：15 项状态聚合测试、前端类型检查及构建、离线手机/桌面 27 项订单页面检查通过；公开文档 13 个操作、172 个字段、109 个引用及 111 个示例完成校验，页面展示和 13 份 Python / 13 份 Node.js 示例语法检查通过。示例未执行真实 API 请求；付款运行时代码未改动。正式部署状态以运维记录为准。

记录受理及资料校验、排队、服务费冻结、分配网络、提链、代理会话检查、打开付款页、账单填写、金额税费、提交付款、结果核实、费用结算或解冻、取消或保留续费、结束。每项带时间、状态、执行耗时和轮次；重建原因及等待重试可追溯。页面15秒刷新，历史订单保留原业务记录，不补造新阶段。

管理员可区分出口地区查询、创建结账单、结账初始化、登录态及账号/订阅查询。出口查询200不代表创建结账单成功。旧curl传输保留经白名单处理的请求编号和网关编号；仅上游明确返回挑战响应头时显示“上游要求安全验证”，不凭403猜测。Cookie、完整响应头和正文不投影。

管理接口只能由管理员访问。页面只消费本站保存的白名单记录；付款核心请求在服务端执行，核心接口地址、凭据、原始报文、完整卡号不投影至订单接口。管理员详情按权限单独返回原账单副本及结账链接，客户接口不返回这些资料。

## 结账链接历史

订单详情的折叠“结账链接历史”中展示实际链接，按轮次显示全文、生成时间与复制按钮。每次实际提链完成时加密留存，重建和付款完成不会覆盖原链接；付款状态继续以原流程为准，查看记录不会重新付款。HTTP部署也支持复制，不会自动访问上游链接。

旧订单仅保留升级时尚在库的链接，生成时间未知时注明“历史保留链接 · 生成时间未记录”。没有生成或已被清理的链接无法恢复；历史链接不代表仍可付款。

## 代理与兼容重建

订单按订阅地区选择代理。IPRoyal geo.iproyal.com 每单创建独立 session，默认 lifetime=1h；已配置的国家和有效寿命保留。全单复用加密保存的端点。旧提链保留原脚本首次地区查询；付款前核对出口是否与提链记录一致。Windows 可经系统外层代理连接供应商，生产默认直接连接供应商；无可用代理禁止直连上游。

新旧提链及订阅按用户后续要求恢复付款前出口一致性检查，保留原代理绑定、有效期和任务租约。仅 geo.iproyal.com 自动生成供应商粘性会话；其他代理保持配置原值。漂移、探测失败、到期或租约失效停止。以下重建配置只影响旧订单的兼容路径。

后台付款配置的“付款前网络会话最多重建次数”默认为2，可设置0～5；0关闭自动重建。只有确认尚未提交扣款的会话失效或出口变化允许重新排队提链。原账单、副本、冻结费用保留，不重复冻结。普通网络安全重试仍按队列重试间隔执行。

已成功、已提交后连接中断、结果未知、需额外验证均不会自动重新扣款；恢复原交易，不重新确认扣款；新协议可能继续原交易待批准、生效和续费动作。原代理会话失效时停止核实并保留待核实，不换出口重付。付款成功后的取消续费失败，仍是“订阅成功，取消自动续费失败”。订阅办理的付款后查询、刷新及取消复用原订单代理会话；独立续费管理继续使用后台全局代理。
